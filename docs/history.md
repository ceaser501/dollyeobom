## 결정 요약 (현재 기준)

| 항목 | 결정 |
|---|---|
| 서비스명 | **돌려봄** (저장소 `dollyeobom`) |
| 타겟 | 초·중학생 + 취업 준비 대학생(공간지각). **1단계는 초등 교육과정** |
| 핵심 기능 | 문제 사진 → 3D 렌더링(회전·확대·터치) + 단계별 해설 |

| 검증용 샘플 | 구글 이미지·블로그에서 실제 문제 사진 30~50장 수집 |
| 우선 제외 | 일반 물리, 공학 도면 (2단계 이후) |

## 2026-10-29

### Q1. 이 서비스, 구현 가능한가? 3D 변환이 잘 될까? 외부 툴과 비용은? 유용한가?

**질문 요지**
- 초·중·대학생 대상. 2D 학습지를 찍으면 3D로 변환해 보여주는 서비스
- 니즈: 물리 공부, 2D 도면 이해, 기업이 요구하는 공간지각 능력
- 기능: 마우스/터치로 회전, 문제 해설, 히스토리, 약점 리포트

**답변 요지**
- **가능하다.** 단, 방식이 성패를 가른다.
  - ❌ 이미지→3D 생성 AI(Meshy, Tripo, Hunyuan3D 등): 선 그림을 물체로 오인하고 치수가 틀린다. 교육용으로 부적합
  - ✅ 비전 LLM이 문제를 해석 → 구조화 데이터(JSON) → Three.js로 렌더링. AI는 "어떤 도형을 어떤 치수로 둘지"만 정한다
- 분야별 난이도
  - 🟢 초·중 입체도형, 취업 공간지각(블록, 전개도, 투상도): 쉬움
  - 🟡 물리: 중간 (3D보다 애니메이션이 효과적)
  - 🟠 공학 도면(3면도→3D): 어려움
- 비용
  - 유료: 비전 LLM API (문제당 대략 수십 원 수준), Mathpix(선택)
  - 무료: Three.js, CadQuery/OpenSCAD, Supabase·Firebase 무료 티어
  - 주의: GeoGebra는 상업적으로 쓰려면 라이선스 필요
- 히스토리·리포트는 기술적으로 쉽고, 품질은 태그 체계 설계에 달려 있다
- 리스크: AI 오해석("이렇게 이해했어요" 확인 단계 필수), 콴다·Gauth와의 경쟁(3D가 차별점), 만 14세 미만 개인정보 동의
- 유용성: **입체도형(초·중)과 공간지각(취준)은 니즈가 강하고**, 대학 도면과 일반 물리는 약하다

### Q2. 강한 니즈 쪽이 맞다. 정리해 달라

**결정:** 타겟을 **초·중학생 입체도형 + 취업 준비 대학생 공간지각**으로 좁힌다.

**정리한 내용**
- 흐름: 촬영 → 해석 확인 → JSON → 3D 렌더링 → 해설 → 태그·히스토리 → 리포트
- 진행 순서: 검증(1~2주) → 프로토타입(2~3개월) → 사용자 테스트 → 확장

### Q3. 초등 커리큘럼부터 시작하자. 교육과정 태그를 붙이고, 교재명은 선택. 어떻게 시작하나?

**결정**
- 1단계는 **초등 교육과정**
- 교육과정 기반 태그 사용 (`중1-입체도형-전개도` 같은 형식)
- 학습지·문제지명은 **선택 항목**

**답변 요지**
- 초등에서 3D가 필요한 단원: 여러 가지 모양, 쌓기나무, 직육면체(겨냥도·전개도), 각기둥과 각뿔, 부피와 겉넓이, 공간과 입체, 원기둥·원뿔·구
  - 대부분 **쌓기나무, 전개도, 회전체** 세 가지 렌더러로 커버된다
- 초등 3~6학년 수학은 검정 교과서라 출판사마다 단원명이 다르다 → **태그 기준 키는 성취기준 코드** (NCIC에서 원문 확보)
- 개발 단계: ① 태그 체계 → ② 검증 스파이크(사진→JSON 정확도) → ③ 3D 렌더러 → ④ MVP 앱 → ⑤ 리포트
- 스택: Next.js + react-three-fiber + Supabase + 비전 LLM API
- 유의: 사용자가 찍은 문제는 본인용으로만 보관하고 추천 문제는 자체 제작. 학부모 계정 → 자녀 프로필 구조

### Q4. 샘플 사진은 구글에서 찾자. 저장소 이름은 "모아콘"과 비슷한 느낌으로

**결정:** 검증 샘플은 **구글 이미지·블로그·카페의 실제 사진**으로 수집한다.

**답변 요지**
- 휴대폰 촬영본 위주로 모으고 스캔본·필기 덮인 사진을 섞는다. 사진마다 정답표 작성
- 수집 이미지는 내부 테스트용으로만 쓰고 저장소에 커밋하지 않는다

**이름 논의 과정**
1. 1차 후보: 돌려봄, 입체봄, 펼쳐콘, 쌓아콘, 찍어봄, 모아큐브
2. "돌려봄은 동사를 줄인 느낌" → 명사형(입체콘, 큐브콘, 삼디콘, 큐비 등) 제안
3. "콘이 아니라 '모아'를 넣어야 한다" → 모아큐브, 모아입체, 모아블록, 모아도형, 모아3D, 모아뷰 제안
4. **최종: "돌려봄"으로 결정**

### Q8. 화면 구성과 API 키 처리

**결정 (화면)**
- 3D 보기와 단계별 해설을 **한 화면**에 함께 보여준다
- **2D 보기 / 3D 보기 전환**을 둔다
- 같은 문제를 **다시 풀어볼 수 있게** 한다 (정답·해설을 가리고 직접 답을 입력 → 채점 → 해설 공개)

**결정 (API 키)**
- 사용자가 매번 키를 넣지 않는다. 키는 **서버 환경변수(비밀값)로 한 번만 등록**하고, 브라우저에는 절대 노출하지 않는다
- 사진 해석 요청은 브라우저 → 우리 서버(API 라우트 또는 Supabase Edge Function) → LLM API 순서로 간다
- 남용을 막으려고 요청 횟수 제한을 둔다
